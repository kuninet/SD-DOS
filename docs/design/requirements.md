# ファイルストリームアクセス対応 要件整理

## 目的
SD上のファイルを、全体をメモリへ展開せずに少しずつ読み出せるストリームアクセス機能をSD-DOSに追加する。第一の利用例は、FM音源などのVGM音楽ファイルをロードしながら演奏するVGM再生サンプル(別途作成)である。

## 背景
現行のSD-DOSは、PC-8001からSDメモリカード上のファイルを扱うための基本機能を持っている。既存の`RBYTE`は任意ファイルの読み込みに使えるが、メモリ上への一括ロードを前提とする処理であり、長いデータを処理の進行に合わせて読み続ける用途には向きにくい。

ストリーム読み出しでは、ファイル全体を展開せず、必要なデータを順に読み出せる経路が必要になる。既存実装では、`FP.asm`の`FETCH_1BYTE`と`INC_FP`が、セクタ境界やクラスタ境界をまたぐ逐次読み込みの候補になる。

## 対象範囲
* SD上の任意ファイルをストリーム読み出しで利用側へ渡すための方式
* FAT16上のファイルを512バイトセクタ境界とFATクラスタ境界をまたいで読むための要件
* PC-8001上で呼び出すコマンドまたはAPIの初期検討
* 既存の`LOAD`、`RBYTE`、CMT/BAS/BIN処理との役割分担

## 初期スコープ
* 任意ファイルを全量メモリに展開せず、必要な分だけ順に読み出せること
* 512バイトセクタ境界をまたいでも、読み出し位置を継続できること
* FATクラスタ境界をまたいでも、次クラスタへ進んで読み出しを継続できること
* 読み出し状態を保持し、利用側(演奏処理など)から継続的にデータを取得できること
* 既存のSD-DOSファイル操作を壊さないこと

## 非スコープ
* VGM再生エンジン本体の実装はVGM再生サンプル側で扱う
* 特定FM音源チップへの出力処理はVGM再生サンプル側で扱う
* 対応するVGMコマンド範囲やタイミング精度の確定はVGM再生サンプル側で扱う
* 既存の`LOAD`や`RBYTE`の仕様変更は前提にしない

## 既存実装の前提
* `RBYTE`は任意ファイルを指定アドレスへ読み込むための入口だが、一括ロード寄りの処理である
* `RAW.asm`の`READ_RAW`は`FETCH_1BYTE`を繰り返してメモリへコピーする
* `FP.asm`の`FETCH_1BYTE`はファイルポインタ位置の1バイトを読み、`INC_FP`で次位置へ進める
* `INC_FP`はセクタ境界で次セクタを読み込み、クラスタ境界ではFATをたどって次クラスタへ進む
* ファイル用バッファは512バイト単位で扱われるため、SD/FAT側の読み出し経路はこの単位を前提に検討する

既存の`LOAD`、`RBYTE`、`READ_RAW`とストリーム読み出しの役割分担は、[LOAD/RBYTE/RAWとストリーム読み出しの役割分担](load-rbyte-raw.md)に整理する。

ストリーム読み出しで保持する状態項目と更新タイミングは、[ストリーム読み出しの状態管理](seq-read-state.md)に整理する。

利用側へ渡す取得単位と既存バッファの再利用範囲は、[ストリーム読み出しの取得単位とバッファ](buffer-unit.md)に整理する。

EOF・エラー・64KBを超えるファイルの扱いは、[ストリーム読み出しのEOF・エラー・長尺ファイルの扱い](eof-error.md)に整理する。

シーク(読み出し位置の任意設定)の要否は、[ストリーム読み出しのシーク機能の要否](seek.md)に整理する。

呼び出し口(BASICコマンドか機械語APIか)は、[ストリーム読み出しの呼び出し口](entry-point.md)に整理する。

エントリポイントとレジスタ仕様の具体形は、[ストリーム読み出しAPI仕様](api-spec.md)に整理する。

## 初期要件
* ファイルを開いた後、利用側が必要なタイミングで次データを取得できること
* 読み出し位置、現在クラスタ、セクタ内位置、ファイル終端を管理できること
* ファイル終端に到達した場合、利用側が終了を判断できる状態を返せること
* 読み出し中のSDアクセスエラーや不正なFATリンクは、初期実装では既存のエラー処理(BASICへのエラー終了)に従う。利用側へ状態として返す経路は将来検討とする
* 既存のバッファ、FAT読み出し、ファイルポインタ処理を可能な範囲で再利用すること
* 既存のファイルバッファを再利用する場合は、既存コマンドとストリーム読み出しが同時に同じバッファを使わないこと
* 同時利用が必要な場合は、ストリーム読み出し用の専用バッファまたは状態構造を別途検討すること
* 既存コマンドの挙動を変える場合は、別途仕様変更として扱うこと

## 未確定事項
初期スコープの未確定事項はすべて確定した。EOF状態の返し方を含む具体形は[ストリーム読み出しAPI仕様](api-spec.md)を参照。

VGM固有の論点(ヘッダ解析、コマンド解釈、音源出力、タイミング制御)はVGM再生サンプル側で整理する。
