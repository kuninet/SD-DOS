# インクリメンタル(ストリーミング)セクタ読みの設計

## 目的

ストリーム読み出しでセクタ境界の1バイト取得が512バイトを一気に読む(約0.1秒のバースト)問題を解消するため、SD-DOSにブロック読みを1バイトずつ進める「ストリーミング読み」経路を追加する。この文書は設計整理であり、実装はこの方針に基づいて行う。

## 背景と前提

ビットバンギングSPIのため、1バイトの読み込みは約820クロック(約0.2ミリ秒)、1セクタ512バイトで約0.1秒かかる。現状のストリーム読み出しは、セクタ境界の1バイト取得時に`READ_FP_SCTR`→`READ_SCTR`→`MMC_READ`で512バイトを一括して`FILE_BFFR`へ読む。この一括読みの間CPUが固まり、VGM再生のもたつきの根本原因になる。

PC-8001にはタイマー割り込みが無いため、再生と読み込みは単線で行う。平均ではSDの読み出し(約5KB/秒)がVGMの消費(数分の曲で約1KB/秒)より速いので、読み込み時間を細かく分割してウェイトの合間に散らせば、平均の余裕の範囲で滑らかに再生できる。バーストのままでは1回のウェイト(1/60秒=約16ミリ秒)に約0.1秒は収まらない。

## 方針

ストリーム読み出しを、`FILE_BFFR`一括読みを使わない**専用のインクリメンタル読み経路**に置き換える。SDのブロック読みトランザクションを開いたまま、`STRM_READ`が要求のたびに1バイトだけクロックして返す。これにより`STRM_READ`1回あたりの時間が約0.2ミリ秒(SD 1バイト分)に固定され、約0.1秒のバーストが無くなる。

既存の`MMC_BRD_CMD`(ブロック読み開始)、`MMC_1RD`(1バイトクロック)、`MMC_BRD_END`(ブロック読み終了)を組み替えて使う。新規の低レベルコードは少ない。

ストリーム読み出しはバイトをレジスタで返すだけなので、専用のセクタバッファは持たない(プレイヤー側のリングバッファが緩衝を担う)。

## 既存経路との分離

- `LOAD`、`RBYTE`、`READ_RAW`、`FILE_BFFR`、`FETCH_1BYTE`/`INC_FP`/`PREP_READ`の一括ロード経路は変更しない
- ストリーム読み出しは`FILE_BFFR`も`FP`系ワークも使わず、専用の位置管理ワークを持つ
- ストリームAPIのエントリ(`STRM_OPEN`=6005H、`STRM_READ`=6008H、`STRM_CLOSE`=600BH)とレジスタ仕様は不変。プレイヤー(VGMPLAY)は無改修

## 位置管理ワーク

ストリーム専用に次を持つ(`FP`系とは別)。

| ワーク | サイズ | 内容 |
|---|---|---|
| STRM_CLSTR | 2バイト | 現在のクラスタ番号 |
| STRM_CSEC | 1バイト | クラスタ内のセクタ番号(0〜SCTRS_PER_CLSTR-1) |
| STRM_BOFS | 2バイト | 現在セクタ内のバイトオフセット(0〜511) |
| STRM_REMAIN | 4バイト | 残りバイト数(既存。DIR_ENTRYのサイズで初期化) |
| STRM_OPEN_BLK | 1バイト | ブロック読みを開いている最中なら非0 |
| STRM_STAT | 1バイト | 00H=未オープン、01H=読み出し中、02H=EOF(既存) |
| SD_SND_OFF | 1バイト | アクセス音抑止(既存) |

物理セクタ番号は、`STRM_CLSTR`から`GET_FIRST_SCTR`で開始セクタを求め、`STRM_CSEC`を足して算出する(都度計算。専用ワークは持たない)。

## STRM_OPEN

1. ワーキングディレクトリを退避し、パス解決(`CHANGE_WDIR`)、エントリ検索(`GET_DENT`、属性=ファイル)。見つからなければ復帰してCY=1、A=01H
2. `STRM_CLSTR`=DIR_ENTRYの開始クラスタ番号、`STRM_CSEC`=0、`STRM_BOFS`=0、`STRM_OPEN_BLK`=0
3. `STRM_REMAIN`=DIR_ENTRYのファイルサイズ、`STRM_STAT`=読み出し中、`SD_SND_OFF`=非0(既存)
4. ブロック読みはここでは開かない(遅延オープン。最初の`STRM_READ`で開く)
5. ワーキングディレクトリを復帰してCY=0

## STRM_READ

1. `STRM_STAT`が「読み出し中」でなければ、状態を返す(未オープン=CY=1,A=01H/EOF到達=CY=1,A=00H)
2. `STRM_REMAIN`が0なら`STRM_STAT`=EOFにしてCY=1、A=00H。開いているブロックがあれば閉じる(後述)
3. `STRM_OPEN_BLK`が0なら、現在セクタのブロック読みを開く:
   - 物理セクタ番号を算出(`GET_FIRST_SCTR`(STRM_CLSTR)+STRM_CSEC)し、`GET_PHYSICAL_ADRS`で`MMCADR`を設定
   - `MMC_BRD_CMD`でブロック読み開始、`STRM_OPEN_BLK`=非0、`STRM_BOFS`=0
4. `MMC_1RD`で1バイト取得、`STRM_BOFS`++、`STRM_REMAIN`--
5. `STRM_BOFS`が512に達したら現在ブロックを閉じて次セクタへ進める(後述)
6. 取得した値をAで返す(CY=0)

## セクタ・クラスタの進行

`STRM_BOFS`が512に達したとき:

1. `MMC_BRD_END`で現在ブロックを閉じ、`STRM_OPEN_BLK`=0、`STRM_BOFS`=0
2. `STRM_CSEC`++
3. `STRM_CSEC`が`SCTRS_PER_CLSTR`に達したら:
   - `STRM_CSEC`=0
   - `NEXT_CLSTR`相当でFATをたどり`STRM_CLSTR`を次クラスタへ更新(FATが0FFFFHならファイル終端。ただし`STRM_REMAIN`によるEOF前判定が先に効くため、正常なファイルでは到達しない)

次の`STRM_READ`が`STRM_OPEN_BLK`=0を見て新しいセクタのブロックを開く(遅延オープン)。

## STRM_CLOSE

`STRM_OPEN_BLK`が非0なら`MMC_BRD_END`でブロックを閉じる(MMCを次のDOS操作のためにクリーンにする)。`STRM_STAT`=未オープン、`SD_SND_OFF`を戻す。

## MMC共有の制約

ブロック読みは`STRM_READ`の呼び出しをまたいで**開いたまま**になる(SDカードはデータを保持し、クロックは任意に中断・再開できる)。開いている間に他のMMCアクセスが起きるとトランザクションが壊れる。

- ストリーム読み出し中は既存のDOSコマンドを使わない前提(既存の制約)を維持する。これによりストリーム以外のMMCアクセスは発生しない
- クラスタ跨ぎのFAT読みは、先に`MMC_BRD_END`でデータブロックを閉じてから行う(FAT読みは別トランザクション)。順序を守ることで競合しない
- FATは`FAT_BFFR`を使い`FILE_BFFR`とは別。ストリームはどちらのバッファも占有しない

## アクセス表示・アクセス音の扱い

既存の一括読み(`MMC_READ`)は`MMC_LED_ON`/`MMC_LED_OFF`を呼び、物理アクセスLED、疑似アクセス音(`SD_SND_OFF`で抑止済み)、画面の`*`表示(`INFO_SW`連動)を伴う。これらは現状「セクタ単位で1回」なので負荷は無視できるが、1バイト単位で呼ぶと無視できなくなる。

インクリメンタル経路は`MMC_READ`を使わず`MMC_BRD_CMD`/`MMC_1RD`/`MMC_BRD_END`を直接呼ぶため、**`MMC_LED_ON`/`MMC_LED_OFF`は呼ばない**。これにより、再生中のデータ読みではLED・`*`表示・音の処理が一切走らず、1バイトあたりのオーバーヘッドが無い。

- 通常のDOS操作(LOAD/FILESなど)は従来どおり`MMC_READ`経由でLED・音・`*`が出る(変更しない)
- `STRM_OPEN`のディレクトリ検索と、稀なクラスタ跨ぎのFAT読みは既存の一括読みを通るため、その瞬間だけLED/`*`が出る(音は`SD_SND_OFF`で抑止)。一時的かつ稀なので影響は小さい
- 再生中も物理LEDをアクセス表示として点けたい場合は、ブロック開閉(セクタ単位、毎秒約10回)で`MMC_LED_ON`/`MMC_LED_OFF`を呼べばよい(負荷は無視できる)。初期実装では呼ばない(シンプル優先)

## クラスタ跨ぎのFAT読み(残課題)

クラスタ跨ぎでは`NEXT_CLSTR`がFATを読むため、ここだけは一括読み(約0.1秒)が残る。ただしFATセクタは`FAT_BFFR`にキャッシュされ、同じFATセクタ内のクラスタ遷移ではSDアクセスが発生しない。2GBのSD(FAT16、1クラスタ=32KB)では、FAT1セクタが多数のクラスタをカバーするためFAT読みは稀。初期実装ではこのバーストを許容し、必要なら後でFATの先読み・分割読みを検討する。

## エラーとEOF

- EOFは`STRM_REMAIN`による取得前判定(既存の方針)。正常終了として扱う
- SDアクセス異常(MMCタイムアウト)は既存どおり非復帰でBASICのエラー処理へ。ストリーム中に発生した場合、開いているブロックの後始末は行われないが、エラー終了なので問題にならない
- `STRM_REMAIN`とFATが整合した正常なファイルでは、クラスタ末尾でのFAT終端到達(`MSG_SCTR_OVERFLOW`相当)に到達しない

## 検証

- 検証ハーネス(`scripts/test_stream_api.py`、`scripts/test_vgmplay.py`)はセクタ読みをホスト側でスタブする。インクリメンタル読みでも、取得バイト列・音源ポート出力列が従来と完全一致することを確認する(機能の回帰)
- ハーネスはMMCの実クロックを模擬しないため、バースト解消(時間的効果)は実機の聴感で確認する
- `STRM_READ`1回が一括読みを起こさないことは、ハーネスのセクタ読みフックの呼ばれ方(1セクタ分が1回でなく、境界をまたぐ取得でのみ1回)で確認できる
