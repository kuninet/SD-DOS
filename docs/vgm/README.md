# VGM再生サンプル(VGMPLAY)

`samples/VGMPLAY.asm` は、SD-DOSのストリーム読み出しAPIを使って SD 上の VGM ファイルを
「ロードしながら演奏する」サンプルプレイヤーである。YM2203 ボード(80H/81H)と
PSG ボード(0A0H/0A1H)へ出力する。VGM 特化の処理はすべてプレイヤー側にあり、
SD-DOS 本体は汎用のストリーム/ディレクトリアクセスのみを提供する。

## 必要なもの

- SD-DOS 本体(ROM)に以下のストリームAPIが入っていること。**SD-DOS を更新したら ROM を焼き直す**こと。
  - `6005H` STRM_OPEN / `6008H` STRM_READ / `600BH` STRM_CLOSE
  - `600EH` STRM_DIRLIST(ディレクトリ列挙。一覧表示に使用)
- VGM はヘッダ付きの**無圧縮**ファイル(`.VGM`)。`.VGZ`(gzip)は非対応。

## ビルド

```
make           # build/VGMPLAY.cmt が生成される
make list      # build/VGMPLAY.asm.log.asz(アセンブルリスト)と .sym も生成
```

## 使い方

1. `LOAD "VGMPLAY.CMT"` でプレイヤーを読み込む
2. VGM が別ディレクトリにあるなら、先に SD-DOS で `CD` しておく(一覧は**現在のディレクトリ**を表示する)
3. 機械語モニタで **`G9000`** で起動(`CMD R` ではなくモニタの Go コマンド)
4. 画面に現在ディレクトリの `*.VGM` が番号付きで一覧表示される
5. **番号 + Enter** で選択 → 再生(Enter で改行してから再生開始)
6. 再生が終わると**メニューに戻る**。続けて別の曲を選べる
7. **`0` + Enter**(または何も入れず Enter)で BASIC へ戻る

> 終了は `RET` ではなく `JP BASIC`(0081H)で行う。モニタの `G` 起動でも安全に BASIC へ戻る。

## タイミングと調整ポイント(POKE)

タイミングはビジーループ近似(PC-8001 にタイマー割り込みが無いため)。PC-8001 は画面表示中の
DMA でCPUの実効クロックが約1.84MHz(4MHzの半分弱)まで落ちるため、各係数は**実機で耳で**
追い込む前提。`LOAD` 後、再生せずに `POKE` で値を変えてから `G9000` で試す。

| アドレス | 変数 | 既定 | 役割 / 調整の向き |
|---|---|---|---|
| `&H9003` | WAIT_KV | `02H` | **全体テンポ**。小さいほど速い |
| `&H9004` | READ_SAMP | `10H`(16) | **SD読みコスト/先読みの積極度**。下げるほど先読みが積極化し、後半のバッファ枯渇(=もったり/引っ掛かり)が減る。下げすぎると短い音符が伸びてもたつく |
| `&H9005` | WRITE_COST | `23H`(35) | **音源書き込みの処理時間補正**。大きいほど、書き込みが密な小節の詰まりを取り戻す(下げすぎるとバッファ枯渇方向) |
| `&H9006` | BUSY_MAX | `00H` | **YM2203 BUSY待ちの上限**(0=無制限)。密な連続書き込みの待ちを頭打ちにする実験用。下げると密小節が軽くなるが、下げすぎると音が濁る恐れ |

### 調整の目安

- **全体が遅い/速い** → `&H9003`(WAIT_KV)で合わせる
- **後半で急にもったり/引っ掛かる**(バッファ枯渇) → `&H9004`(READ_SAMP)を**下げる**(例: 1E→16)。
  これが一番効く。下げすぎると短い音符が水増しされるので、滑らかさと音価の両立する一番低い値を探す
- **密な小節だけテンポが詰まる**(書き込み多い箇所) → `&H9005` を上げる、または `&H9006` を下げる
- 先読みリングバッファは 16〜18KB(プレイヤー終端が N-BASIC 高位ワークの手前に収まる範囲)。
  これ以上増やしても後半の不足は構造的に残るため、上記の READ_SAMP 調整で対応する

### 最終手段

どうしてもテンポを変えずに完全に滑らかにしたい場合は、**再生中だけ画面を OFF にして DMA を止め、
実効クロックを ~4MHz に戻す**(CPU が約2倍)方法がある。実効速度が変わるため各係数の再調整が必要。
