# VGMストリーミング再生対応 要件整理

## 目的
SD上に置いたFM音源などのVGM音楽ファイルを、PC-8001で少しずつロードしながら演奏できるようにする。

## 背景
現行のSD-DOSは、PC-8001からSDメモリカード上のファイルを扱うための基本機能を持っている。既存の`RBYTE`は任意ファイルの読み込みに使えるが、メモリ上への一括ロードを前提とする処理であり、長い音楽データを演奏の進行に合わせて読み続ける用途には向きにくい。

VGM再生では、ファイル全体を展開せず、必要なデータを順に読み出せる経路が必要になる。既存実装では、`FP.asm`の`FETCH_1BYTE`と`INC_FP`が、セクタ境界やクラスタ境界をまたぐ逐次読み込みの候補になる。

## 対象範囲
* SD上のVGM音楽ファイルを演奏処理へ渡すための逐次読み込み方式
* FAT16上のファイルを512バイトセクタ境界とFATクラスタ境界をまたいで読むための要件
* PC-8001上で呼び出すコマンドまたはAPIの初期検討
* 既存の`LOAD`、`RBYTE`、CMT/BAS/BIN処理との役割分担

## 初期スコープ
* VGMファイルを全量メモリに展開せず、必要な分だけ順に読み出せること
* 512バイトセクタ境界をまたいでも、読み出し位置を継続できること
* FATクラスタ境界をまたいでも、次クラスタへ進んで読み出しを継続できること
* 読み出し状態を保持し、演奏処理側から継続的にデータを取得できること
* 既存のSD-DOSファイル操作を壊さないこと

## 非スコープ
* 初期要件整理の段階では、VGM再生エンジン本体の実装は扱わない
* 初期要件整理の段階では、特定FM音源チップへの出力処理は確定しない
* 初期要件整理の段階では、対応するVGMコマンド範囲やタイミング精度を確定しない
* 初期要件整理の段階では、既存の`LOAD`や`RBYTE`の仕様変更は前提にしない

## 既存実装の前提
* `RBYTE`は任意ファイルを指定アドレスへ読み込むための入口だが、一括ロード寄りの処理である
* `RAW.asm`の`READ_RAW`は`FETCH_1BYTE`を繰り返してメモリへコピーする
* `FP.asm`の`FETCH_1BYTE`はファイルポインタ位置の1バイトを読み、`INC_FP`で次位置へ進める
* `INC_FP`はセクタ境界で次セクタを読み込み、クラスタ境界ではFATをたどって次クラスタへ進む
* ファイル用バッファは512バイト単位で扱われるため、SD/FAT側の読み出し経路はこの単位を前提に検討する

既存の`LOAD`、`RBYTE`、`READ_RAW`とVGM逐次読み出しの役割分担は、[LOAD/RBYTE/RAWとVGM逐次読み出しの役割分担](load-rbyte-raw.md)に整理する。

## 初期要件
* ファイルを開いた後、演奏処理が必要なタイミングで次データを取得できること
* 読み出し位置、現在クラスタ、セクタ内位置、ファイル終端を管理できること
* ファイル終端に到達した場合、演奏処理側が終了を判断できる状態を返せること
* 読み出し中にSDアクセスエラーや不正なFATリンクを検出した場合、呼び出し側へ異常を伝えられること
* 既存のバッファ、FAT読み出し、ファイルポインタ処理を可能な範囲で再利用すること
* 既存のファイルバッファを再利用する場合は、既存コマンドとVGM逐次読み出しが同時に同じバッファを使わないこと
* 同時利用が必要な場合は、VGM用の専用バッファまたは状態構造を別途検討すること
* 既存コマンドの挙動を変える場合は、別途仕様変更として扱うこと
