# VGM逐次読み出しの状態管理

## 目的

VGM再生向け逐次読み出しで保持すべき状態項目と更新タイミングを、既存のファイルポインタ処理(`FP.asm`)の調査結果に基づいて整理する。この文書は設計整理であり、コード変更は含まない。

## 既存の読み出し状態

VGM逐次読み出しで再利用候補となる既存の読み出し状態ワークは、MAIN.asm で定義されている。

| ワーク名 | サイズ | 役割 |
|---------|--------|------|
| `FP` | 4バイト | ファイルポインタ。ファイル先頭からのバイト位置。最大値はファイルサイズ |
| `FP_CLSTR` | 2バイト | FPと結びつくファイルのカレントクラスタ#。FPと連動して変化する |
| `FP_CLSTR_SN` | 2バイト | FPが示すアドレスがファイル先頭から何番目のクラスタに含まれるか(クラスタ#ではない) |
| `FP_SCTR_SN` | 1バイト | FPが示すアドレスがクラスタ内の何番目のセクタに含まれるか(セクタ#ではない) |
| `FILE_BFFR_STRCT` | 7バイト | ファイル用バッファ構造体。+0〜3=読み込み済みセクタ#、+4〜5=バッファ先頭アドレス(FILE_BFFRを指す)、+6=更新フラグ |
| `TGT_CLSTR` | 2バイト | ターゲットファイルの開始クラスタ#。ファイル名解決時にセットされる |
| `DIR_ENTRY` | 32バイト | ディレクトリエントリ情報。IDX_SIZE位置に4バイトのファイルサイズを持つ |

また、CMT読み込み向けのコールバックフラグ `IS_CALLBACK` が存在し、PREP_READ(CMT.asm) が冒頭でクリアする。

### FPのビット構造

FP(4バイト)のビット配置は次のとおり。

```
bit0〜8   (9bit)  : セクタ内オフセット値 0〜511
bit9〜14  (6bit)  : クラスタ内セクタシリアル#
bit15〜30 (16bit) : クラスタシリアル#
```

## 状態の更新タイミング

既存の読み込み経路では、ファイルポインタ関連ワークが以下のタイミングで更新される。

### 初期化時(PREP_READ/INIT_FP)

`PREP_READ`(CMT.asm)は読み込み前の共通初期化として、次の手順を実行する。

* IS_CALLBACK クリア
* TGT_CLSTR から INIT_FP を呼び出す
* IX = FILE_BFFR_STRCT に設定
* 先頭セクタを READ_FP_SCTR で読み込む

`INIT_FP`(FP.asm)は HL = 開始クラスタ# を受けて、以下を初期化する。

* FP = 0
* FP_CLSTR = 開始クラスタ#
* FP_SCTR_SN = 0
* FP_CLSTR_SN = 0

### 1バイト取得時(FETCH_1BYTE)

`FETCH_1BYTE`(FP.asm)は次の処理を実行する。

* FP2BP(バッファ内アドレスを求める)
* A に1バイト読み出す
* INC_FP でファイルポインタを進める

内部で EXX(裏レジスタ)を使用する。IX = バッファ構造体ポインタが前提。

### セクタ境界時(INC_FP→READ_FP_SCTR)

`INC_FP`(FP.asm)がファイルポインタを+1した時、FP の下位9bit が0になる(セクタ境界)場合、次の処理が実行される。

* FP_SCTR_SN を再計算
* FP_SCTR_SN が0でなければ、READ_FP_SCTR でセクタ#を計算してバッファへ読み込む
* LOAD_BFFR(BUFFER.asm) が目的セクタをバッファへ読み込む。既にバッファ済みなら何もしない。違えば(更新フラグが立っていれば書き戻してから)READ_SCTR で読み込む

### クラスタ境界時(INC_FP→NEXT_CLSTR→READ_FP_SCTR)

`INC_FP`がセクタ境界で FP_SCTR_SN が0になる(クラスタ境界)場合、次の処理が実行される。

* NEXT_CLSTR(FP.asm) で次クラスタへ進む
  * FP_CLSTR_SN++
  * 現在クラスタのFATエントリを読んで FP_CLSTR を更新
  * FATが0FFFFH(ファイルエンド)なら Z=1 を返す
* 次クラスタが0FFFFH なら MSG_SCTR_OVERFLOW でエラー経路(JP ERR)へ進む。呼び出し側へ戻らない
* 次クラスタが有効なら READ_FP_SCTR で次セクタをバッファへ読み込む

### 低レベル読み込み(READ_SCTR)

`READ_SCTR`(FS.asm) → `MMC_READ`(MMC.asm) がSDからの実読み込みを実行する。タイムアウト時は MMC_TIMEOUT からERROR へジャンプし、呼び出し側へ戻らない。

## 既存経路のEOFとエラーの扱い

### EOF判定は呼び出し側の責務

低レベル読み出し経路(`FETCH_1BYTE`/`INC_FP`)はEOF判定を持たない。`READ_RAW`(RAW.asm)はDIR_ENTRY のファイルサイズを BC レジスタに取り、1バイトごとにデクリメントして0になったら停止する。つまり、読み出し量の管理は呼び出し側の責務である。

`READ_RAW`はファイルサイズが10000H(64KB)以上ならOUT_OF_MEMORYでエラーにする。

### エラー経路は非復帰設計

次の異常は、いずれも呼び出し側へ戻らずにエラー終了する。

* `INC_FP`がクラスタ境界で`NEXT_CLSTR`を呼び、次クラスタが0FFFFHだった場合は、`MSG_SCTR_OVERFLOW`のエラー経路(`JP ERR`)へ進む
* SDアクセスのタイムアウトは、`MMC_TIMEOUT`から`ERROR`へジャンプする

このため、現状の低レベル読み出し経路には、異常を呼び出し側へ状態として返す仕組みがない。

### 境界先読みによるEOF時の注意

`INC_FP`は境界をまたぐたびに次のセクタを先読みする。このため、ファイルサイズがクラスタサイズちょうどの倍数になっているファイルでは、最終バイトの`FETCH_1BYTE`に続く`INC_FP`が`NEXT_CLSTR`で0FFFFHに到達し、コード上はエラー経路(`JP ERR`)へ進む。`READ_RAW`も最終バイト取得時に`INC_FP`を通るため、この条件は既存経路にも当てはまる。

VGM逐次読み出しでは、終端付近でFPを進める前にEOFを判定するなど、最終バイト取得時の`INC_FP`の扱いを設計に織り込む必要がある。

## VGM逐次読み出しで必要な状態項目(案)

既存FP系ワークの再利用に加えて、次の状態項目が必要になると考えられる。

### EOF判定用のサイズ管理

* 残りバイト数、または読み出し済みバイト数とファイルサイズの組
* `READ_RAW`と同様に`DIR_ENTRY`のファイルサイズから初期化する
* 低レベル経路はEOF判定を持たないため、ファイル終端を認識するための必須項目になる

### EOF到達フラグ

* `INC_FP`の非復帰エラーとは別に、正常なファイル終端に到達したことを示す状態
* 演奏処理側が終了判定できる状態として返す

### エラー状態

* SDアクセス異常や不正なFATリンクを呼び出し側へ返すための状態
* 既存エラー経路が非復帰である点をどう扱うかは、EOF・エラー・長尺ファイルの扱いの整理で決める

### 読み出し中フラグ

* VGM用の逐次読み出しが進行中かを示す状態
* 既存コマンドと`FILE_BFFR_STRCT`を同時に使わない前提を運用するために必要になる

## 再利用範囲と制約

VGM逐次読み出し向けに再利用可能な既存処理は以下のとおり。

### 再利用候補

* `INIT_FP`(FP.asm): ファイルポインタ系ワークを初期化する
* `FETCH_1BYTE`(FP.asm): 現在位置の1バイトを読み、FPを進める
* `INC_FP`(FP.asm): ファイルポインタを進め、境界をまたぐ処理を担当する
* `NEXT_CLSTR`(FP.asm): FATをたどって次クラスタへ進む
* `READ_FP_SCTR`(FP.asm): FP関連ワークからセクタ#を計算し、バッファへ読み込む

### 制約

* `FETCH_1BYTE` が内部で EXX(裏レジスタ)を使用する
* `FETCH_1BYTE` は IX = FILE_BFFR_STRCT ポインタが前提
* `FETCH_1BYTE`/`INC_FP` の使用は FILE_BFFR を占有する(既存コマンドとの同時利用不可)
* `INC_FP` は既存ファイル終端エラーの非復帰経路を変えない
* 境界先読み時のクラスタ境界ちょうどEOFの挙動に注意が必要
